## 1. 런칭 당일 전환 순서

> 순서대로. 각 단계 뒤 Vercel 재배포가 필요한 것은 `NEXT_PUBLIC_*`(빌드 시 박힘) 때문.

1. **예시 상품 비공개 + 런칭 신상 공개** (0-11) — Shopify Admin
2. Vercel `NEXT_PUBLIC_SITE_URL` = `https://shop.applebuttercollege.com` (현재 `abc-store-sigma.vercel.app` — 바꾸기 전 현재 값 확인)
3. Vercel `CHECKOUT_PAUSED` = `false` (또는 삭제)
4. **재배포** → `https://shop.applebuttercollege.com/robots.txt`의 Sitemap 줄이 shop 주소인지 확인
5. 아래 시나리오 ⓢ~⑦ 실행 (실결제는 소액 → 확인 후 환불)
6. 토스에 실거래 URL(`https://shop.applebuttercollege.com`) 변경 알림
7. Search Console > Sitemaps에 `sitemap.xml` 제출 (2번 이후여야 URL이 shop 주소로 나옴)
8. Meta 픽셀/이벤트 관리자 도메인에 shop 주소 추가

## 시나리오 ① 카드 결제 — "주문이 정확히 꽂히는가"

> 이음새: **토스 confirm ↔ Shopify 주문 생성**

1. 모바일에서 상품 1개 장바구니 → 체크아웃
2. 배송지 입력 — **이메일·우편번호 5자리 필수** (비우면 결제 버튼에서 막혀야 정상)
3. 카드 결제 (소액 상품 권장)
4. 완료 페이지 확인 → **새로고침** (멱등성: 중복 주문이 생기면 안 됨)

**확인 포인트 (Shopify Admin > 주문):**
- [ ] 주문 1건 생성, `paid` 상태
- [ ] **주문 총액 = 카드 결제액** (상품 + 배송비 일치)
- [ ] 배송비가 별도 라인(shipping_lines)으로 표시
- [ ] 고객 이메일이 주문에 저장됨
- [ ] 해당 variant **재고 1 감소**
- [ ] 새로고침해도 주문은 여전히 1건

**실패 시:** Vercel 함수 로그에서 `[checkout/confirm]` / `[createShopifyOrder]` 검색.

**정리:** 테스트 주문은 Shopify에서 취소(`restock` 체크) + 토스 대시보드에서 결제취소.

## 시나리오 ② 계좌이체(퀵) — "이체하면 바로 주문이 꽂히는가"

> 이음새: **토스 계좌이체 confirm ↔ Shopify 주문 생성** (가상계좌·웹훅 아님 — 이체 완료 시점에 즉시 paid)

1. 결제수단 **계좌이체**로 주문 → 본인 계좌에서 이체 인증
2. 완료 페이지 → 새로고침 (중복 주문 없어야 정상)

**확인 포인트:**
- [ ] Shopify 주문 1건, 바로 `paid`
- [ ] 주문 총액 = 이체액
- [ ] (Meta Events Manager) Purchase 이벤트 수신

**실패 시:** Vercel 로그 `[checkout/confirm]` 확인.

**정리:** ③④로 반품·환불까지 이어서 테스트 (계좌이체도 원계좌로 자동 환불).

## 시나리오 ③ 반품 접수 — "신청이 관리자까지 닿는가"

> 이음새: **고객 폼 ↔ Shopify returnCreate ↔ Supabase ↔ 관리자 화면**

1. ①의 주문을 **발송 처리(fulfill)** 해둔다 (반품은 발송된 주문만 가능)
2. `/ko/returns`에서 주문번호 + 이름으로 조회 → 반품 신청 (무통장 주문이면 환불계좌 입력란이 떠야 정상)
3. `/admin/returns` 접속

**확인 포인트:**
- [ ] 처리대기 목록에 신청 건 표시 (사유·상품·환불계좌)
- [ ] **CSV 다운로드** → 엑셀에서 한글 정상, 환불계좌 포함
- [ ] Shopify 주문에 Return 생성됨

### 🔴 회귀 테스트 — 반품 사유 "메모" 필드 (2026-09-22 버그 수정분)

> **배경:** `submitReturnRequest`가 잘못된 필드(`customerNote`)를 써서, **메모를 채운 반품만** `returnCreate`가 통째 실패하던 잠복 버그가 있었다(PR #59, `returnReasonNote`로 수정). 빈 메모는 통과하므로 **메모를 반드시 채워서** 테스트해야 회귀를 잡는다.

- [ ] **메모 칸을 채워서** 반품 제출 → **성공 화면**(에러 아님)
- [ ] 메모 **비워서**도 제출 → 성공 (양쪽 다 되어야 정상)
- [ ] Shopify 주문의 Return에 메모(returnReasonNote) 반영 확인

**로그인 UI 테스트용 픽스처:** 주문 **#1044**(발송완료, `philoleben@gmail.com` 계정 연결, `test-return-ui` 태그). 로그인 후 `/ko/returns`에서 바로 보임. **테스트 후 정리 필요**(반품취소 + 주문삭제, 재고는 bypass라 무영향).

> ⚠️ 순서: **PR #59 배포(main 머지 → Vercel) 후** 테스트할 것. 배포 전이면 메모 채운 반품이 실패한다(버그가 아직 라이브라서).

## 시나리오 ④ 환불 완료 — "고객이 알게 되는가"

> 이음새: **관리자 처리 ↔ Resend 메일 ↔ 고객**
> 전제: 0-7 (Resend 인증 완료)

1. `/admin/returns`에서 ③의 건을 `수거승인 → 수령완료` 순서로 진행
2. 수령완료 카드의 **"카드 자동 환불 N원"** 버튼 클릭 (카드·계좌이체 공통 — Toss 부분취소 자동)
3. 메일 확인

**확인 포인트:**
- [ ] 토스 상점관리자에서 해당 결제 **부분취소**(반품배송비 7,000원 차감액) 확인
- [ ] Shopify 주문: `PARTIALLY_REFUNDED` + Return `CLOSED` + 반품 상품 재고 복원
- [ ] **고객 이메일**로 "반품 환불 완료 안내" 수신 (체크아웃에 적은 주소)
- [ ] 관리자(ADMIN_EMAIL)에도 BCC 사본 도착
- [ ] 경고 알림("환불은 완료됐습니다…")이 뜨면 Shopify 반영만 실패 → Shopify에서 수동 환불 기록 (`docs/refund-operations.md`)

## 시나리오 ⑤ Q&A 문의 — "질문이 답변으로 돌아오는가"

> 이음새: **고객 폼 ↔ Supabase ↔ 관리자 ↔ 답변 메일** (CS 단일 채널이므로 런칭 필수)
> 전제: 0-7 (Resend 인증 완료)

1. `/ko/qa/new`에서 **분류별 동작 먼저 확인**:
   - [ ] `교환/반품`·`불량/오배송` 선택 → **폼이 막히고 `/returns`로 유도** (인터셉트 — 교환 정책의 관문)
   - [ ] `환불` 선택 → 주문번호 입력란 필수로 표시
2. `배송` 분류로 테스트 질문 등록 (이메일 입력)
3. 관리자 메일함: **"[새 문의]" 알림** 도착 확인
4. `/admin/qa`에서 해당 질문 → **답변 템플릿** 선택해 답변 등록
5. 고객 메일함: **답변 알림 메일** 도착 확인 (질문 등록 시 적은 주소)

**확인 포인트:**
- [ ] 분류 인터셉트 2종 (교환/반품 → /returns 유도)
- [ ] 새 문의 → 관리자 알림 메일
- [ ] 답변 템플릿 목록이 뜨고 사용 가능 (Supabase `answer_templates` — 비어 있으면 템플릿 등록부터)
- [ ] 답변 등록 → 고객 알림 메일 (ko/ja locale 맞게)

## 시나리오 ⑥ Q&A 단순환불 — "회수 없는 환불이 고객까지 닿는가"

> 이음새: **Q&A 환불 분류 ↔ AdminRefundPanel(refund_requests) ↔ 환불완료 메일**
> ③④의 `/returns` 정식 반품과는 **별개 테이블·별개 화면**이다 (`docs/refund-operations.md` §1)

1. `환불` 분류로 문의 등록 (주문번호 포함)
2. `/admin/qa/[id]`의 **AdminRefundPanel**에서 환불 요청 등록 (고객명·이메일·금액·결제수단)
3. `처리중 → 완료`로 상태 변경
4. 고객 메일함: **"환불이 완료되었습니다"** 메일 도착 확인

**확인 포인트:**
- [ ] refund_requests 등록 → 상태 변경 흐름 작동
- [ ] 완료 처리 → 고객 환불완료 메일 (ko/ja)
- [ ] 실제 환불 실행 잊지 말 것 (카드: 토스 취소 / 무통장: 이체) — §7 체크리스트

## 시나리오 ⑦ 로그인·마이페이지 — "내 주문이 내 계정에 보이는가"

> 이음새: **OIDC 로그인 ↔ Shopify Customer ↔ Admin API로 만든 주문의 연결**
> ⚠️ 핵심 함정: 주문은 Admin API로 생성되며 **이메일로만** 고객과 연결된다.
> 로그인 계정의 이메일 ≠ 체크아웃에 입력한 이메일이면 **주문내역에 안 보인다.**

1. 로그인 (Shopify 계정) → 헤더에 로그인 상태 반영 확인
2. **로그인 계정과 같은 이메일**로 체크아웃 입력 → 카드 결제 (①과 겸해도 됨)
3. `/account/orders`에서 방금 주문이 목록에 보이는지 확인
4. 주문 상세 → **주문 취소** 실행
5. `/account/addresses`에서 배송지 추가 → 수정 → 삭제

**확인 포인트:**
- [ ] 로그인/로그아웃 왕복 (헤더 상태 포함)
- [ ] **체크아웃 이메일 = 계정 이메일인 주문이 주문내역에 표시** ← 헤드리스 연결의 핵심
- [ ] 일부러 **다른 이메일**로 주문 1건 → 주문내역에 안 보이는 것도 확인 (한계 인지용)
- [ ] 주문 취소 → Shopify에서 취소 상태 + **재고 복원** 확인 (결제 환불은 토스에서 별도 — §7 체크리스트)
- [ ] 배송지 추가/수정/삭제 반영

**실패 시 (주문이 안 보임):** Shopify Admin > 고객에서 해당 이메일 고객에 주문이 연결됐는지 확인. 연결 자체가 안 되면 주문 생성(email 필드) 또는 Customer Account API 조회 범위 문제.
