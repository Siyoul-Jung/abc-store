# CS 담당자 고통점 발굴 가이드

> 목적: 메이크샵 시절 CS 담당자가 **실제로 겪던 불편**을 끌어내, Shopify 헤드리스로 넘어갈 때
> 원만하게 해결하기 위한 인터뷰 도구.
> 설문이 아니라 **대화**용. 직원과 마주 앉아 15~30분, 아래 순서대로 따라가며 메모.

---

## 인터뷰 진행 원칙

1. **추상적으로 묻지 말 것.** "불편한 거 있어요?" → ❌ ("괜찮았어요"만 돌아옴)
2. **구체적 사건을 재생할 것.** "지난주에 처리한 문의 중 제일 귀찮았던 거 하나만, 처음부터 끝까지 어떻게 했는지 보여주세요." → ✅
3. **시간을 묻을 것.** "그거 한 건에 몇 분 걸려요?" / "하루에 몇 번 이걸 반복해요?" — 빈도 × 시간이 큰 게 1순위.
4. **해결책을 직원이 말하게 하지 말 것.** 직원은 "메이크샵에 ○○기능 넣어주세요"라고 도구에 갇혀 말함.
   우리가 듣고 싶은 건 기능이 아니라 **불편 그 자체**.
5. **우리 시스템이 이미 푸는 건 즉석에서 안심시킬 것.** (아래 표의 ✅ 항목)

---

## 발굴 표 — 영역별 흔한 고통 · 던질 질문 · 우리 시스템 현재 상태

> 상태 범례: ✅ 이미 해결 · ⚠️ 부분 해결(데이터/설정 필요) · ❌ 아직 없음(만들지 결정)

### A. 문의가 여러 곳에 흩어짐
- **흔한 고통:** 게시판 + 전화 + 카톡 + 네이버톡톡 + 인스타 DM에 문의가 분산 → 어디에 답했는지 추적 불가
- **던질 질문:** "고객 문의가 주로 어디로 들어왔어요? 한 곳이었어요, 여러 군데였어요?"
- **우리 상태:** ✅ Q&A 게시판 **단일 채널** 정책 확정. 단, ⚠️ 전화/카톡으로 오던 고객을 게시판으로 **유도하는 마찰**은 남음 → 직원이 이걸 부담스러워하는지 확인.

### B. 고객이 누구고 뭘 샀는지 찾기
- **흔한 고통:** 고객이 주문번호 안 적음 → 이름·전화로 메이크샵 주문 검색 → 매 문의마다 반복
- **던질 질문:** "문의 들어오면 그 고객 주문 내역을 어떻게 찾았어요? 시간 얼마나 걸렸어요?"
- **우리 상태:** ✅ 답변 화면 오른쪽에 **고객 Shopify 주문 내역 자동 표시** (검색 불필요). 직원에게 보여주면 안심 포인트.

### C. 같은 답변 반복 타이핑
- **흔한 고통:** "배송 며칠 걸려요?" "사이즈 어떻게 봐요?" 같은 질문에 매번 처음부터 타이핑
- **던질 질문:** "제일 자주 받은 질문 5개만 꼽으면요? 그거 답변 어떻게 했어요 — 복붙? 새로 타이핑?"
- **우리 상태:** ⚠️ 템플릿 기능은 구현됨, **내용이 비어있음**. → 직원이 꼽은 자주 묻는 질문 5개가 그대로 초기 템플릿이 됨. **이 질문의 답이 곧 할 일.**

### D. 새 문의가 온 걸 모름
- **흔한 고통:** 관리자 게시판을 계속 새로고침 / 늦게 발견해서 답변 지연
- **던질 질문:** "새 문의 들어온 거 어떻게 알았어요? 알림이 왔어요, 아니면 직접 들어가서 확인했어요?"
- **우리 상태:** ⚠️ 새 문의 시 **담당자 메일 알림** 구현됨 (Vercel 키 등록하면 작동). → 직원 메일 주소를 알림 수신처로 넣을지 확인.

### E. 교환·반품 접수가 번거로움
- **흔한 고통:** 송장번호·환불계좌를 게시판 댓글로 주고받음 → 누락·오타·여러 번 왕복
- **던질 질문:** "교환이나 반품 들어오면 어떤 정보를 받아야 했어요? 그거 받는 과정에서 막힌 적 있어요?"
- **우리 상태:** ✅ `/returns` 전용 폼이 결제수단 감지 + 계좌/사유를 **한 번에 수집**. 교환은 "반품 후 재구매"로 정책 단순화. → 직원이 이 정책 변화를 이해하는지 확인.

### F. 비회원·비밀번호 분실 문의
- **흔한 고통:** 비회원이 자기 글 못 찾음 / 비번 분실 → 본인 확인 수동 처리
- **던질 질문:** "비회원 문의나 '내 글 어디 갔어요' 같은 문의 많았어요? 어떻게 처리했어요?"
- **우리 상태:** ✅ 비회원 글은 비밀번호 + **이메일 열람 링크**(24h)로 본인 확인 자동화. → 수동 처리 부담 사라짐.

### G. 어디서 처리하나 (기기·환경)
- **흔한 고통:** PC에서만 관리자 접근 가능 → 외근·퇴근 후 대응 불가, 혹은 메이크샵 관리자가 느림
- **던질 질문:** "CS 답변 주로 PC에서 했어요, 폰에서도 했어요? 관리자 화면이 느리거나 답답한 적 있었어요?"
- **우리 상태:** ⚠️ `/admin/qa`는 반응형이지만 **모바일 최적화는 미검증**. → 직원이 폰으로도 답하길 원하면 별도 점검 필요.

### H. 진상·분쟁 에스컬레이션
- **흔한 고통:** 답변에 불만족한 고객, 환불 분쟁 → 혼자 감당 / 사장에게 넘기는 절차 불명확
- **던질 질문:** "혼자 해결 안 되는 문의는 어떻게 했어요? 사장님한테 넘기는 기준이나 방법이 있었어요?"
- **우리 상태:** ❌ 에스컬레이션 절차 없음. → 직원 ↔ 사장 인계 규칙이 필요한지 결정 ([cs-workflow-checklist.md](cs-workflow-checklist.md) SLA/에스컬레이션 항목과 연결).

### I. 운영 부담·통계
- **흔한 고통:** 하루 몇 건인지, 주말 대응 의무인지 불명확 → 항상 대기하는 심리적 부담
- **던질 질문:** "하루에 문의 대략 몇 건이었어요? 주말·밤에도 답해야 했어요?"
- **우리 상태:** ❌ SLA·운영시간 정책 미정. 통계 화면 없음. → 응답 목표시간·운영시간 정하면 직원 부담이 명확해짐(=오히려 안심).

## 인터뷰 후 — 분류하고 우선순위 매기기

직원이 말한 고통을 표의 상태로 분류:

- **✅로 분류됨** → "그건 새 사이트에서 이미 자동이에요" 하고 직원 안심시키기. (만들 것 없음)
- **⚠️로 분류됨** → 데이터/설정만 채우면 됨. 가장 빠른 실해결:
  - C(템플릿) → 직원이 꼽은 자주 묻는 질문 5개로 초기 템플릿 입력
  - D(알림) → Vercel `RESEND_API_KEY` 등록 + 직원 메일 수신 설정
- **❌로 분류됨** → 직원이 **실제로 아파하는 것만** 새로 만들지 결정. 안 아픈 건 만들지 않음.

> 원칙: 빈도 × 시간이 큰 고통부터. 직원이 "이건 진짜 매번 짜증났어요"라고 말한 것 1~2개만
> 먼저 해결해도 체감 만족도가 크게 오름. 전부 다 풀려고 하지 말 것.
