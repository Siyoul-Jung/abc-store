# 환불 운영 가이드 (Refund Operations Runbook)

> 환불 요청이 들어왔을 때 **무엇을, 어디서, 어떻게** 처리할지 정리한 운영 매뉴얼.
> 코드에 흩어진 환불 로직 + 팀 결정사항을 한 장으로 모음. 운영 담당자용.
> 관련 코드: `lib/actions/returns.ts`, `lib/actions/order.ts`, `app/admin/returns`, `app/admin/qa`, `components/returns/ReturnForm.tsx`

---

## 0. 한눈에 — 결제수단 × 요청유형 매트릭스

| 상황 | 접수 경로 | 돈 돌려주는 법 | 비고 |
|---|---|---|---|
| **카드 + 반품**(상품 회수 O) | `/returns` → `/admin/returns` | 토스 대시보드 결제취소 *(현재 수동, 자동화 미구현)* | 고객에겐 "자동환불"로 안내됨 ⚠️ |
| **무통장 + 반품**(회수 O) | `/returns` → `/admin/returns` | 고객 환불계좌로 직접 이체 | 폼에서 계좌 수집함 |
| **카드 + 단순환불**(회수 X) | Q&A `환불` 분류 → `/admin/qa` | 토스 대시보드 결제취소 | 계좌 불필요 |
| **무통장 + 단순환불**(회수 X) | Q&A `환불` 분류 → `/admin/qa` | 고객 계좌로 이체 | **계좌 미수집 → 고객에게 따로 받아야 함** ⚠️ |

## 1. 두 접수 경로 (왜 갈리나)

환불은 **상품을 돌려받느냐**로 길이 갈린다.

- **경로 ① 정식 반품** — 상품 회수가 필요한 경우.
  `/returns` 전용 폼 → Shopify `returnCreate` + Supabase `return_requests` → `/admin/returns`에서 처리.
  Q&A 새 문의에서 `교환/반품`·`불량/오배송` 분류를 고르면 **폼이 막히고 이 경로로 유도**된다
  (`NewQuestionForm.tsx`의 `isReturn` 인터셉트 — "계좌 등 개인정보 안전 처리" 목적).

- **경로 ② 단순 환불** — 상품 회수 없이 돈만 돌려주는 경우(불량 일부 보상, 호의 환불 등).
  Q&A `환불` 분류로 접수 → 관리자가 `/admin/qa/[id]`의 **AdminRefundPanel**에서 등록 → Supabase `refund_requests`.

> ⚠️ 두 경로는 **별개 테이블·화면**이다. "지금 처리할 환불"을 보려면 양쪽(`/admin/returns`, `/admin/qa`)을 모두 확인해야 한다.

---

## 2. 결제수단 자동 감지 (구현됨 ✅)

`/returns` 폼은 주문 조회 시 결제수단을 **자동 판별**한다.

- `lookupOrder()` (`lib/actions/returns.ts`)가 Shopify `paymentGatewayNames`를 읽음
  → `manual`/`bank`/`vbank` 포함 = **무통장**, 그 외 = **카드**.
- `ReturnForm.tsx`:
  - **카드** → 환불계좌 입력 없음 + "승인 후 카드로 자동 환불" 안내 문구.
  - **무통장** → 환불계좌(은행/번호/예금주) 입력란 노출.

---

## 3. 결제수단별 실제 환불 방법

### 카드
- **현재(임시): 토스 대시보드에서 수동 결제취소.**
  Shopify 주문 → `note_attributes`의 `toss_payment_key` 확인 → 토스 상점관리자(dashboard.tosspayments.com)에서 해당 결제 검색 → "결제취소"(부분취소 시 금액 지정). 카드로 자동 환급됨.
- **계획(미구현): `/admin/returns`에서 원클릭 자동환불.**
  Toss `POST /v1/payments/{paymentKey}/cancel` 호출을 "환불완료" 버튼에 연결. `paymentKey`는 이미 주문에 저장돼 있어 연동만 하면 됨.

> ⚠️ **갭 주의**: 고객에겐 카드 반품 시 "자동환불"로 안내되지만(`ReturnForm`), 백엔드 자동화는 아직 없다. **현재는 관리자가 토스 대시보드에서 직접 취소해야 한다.** 빠뜨리면 고객은 "자동이라더니 환불이 안 됐다"가 된다.

### 무통장(가상계좌)
- 돈이 이미 입금됐으므로 환불 = **판매자가 고객 환불계좌로 직접 이체**. PG가 대신 못 함(본질적 수동).
- 계좌 정보: 반품은 폼에서 수집됨(`return_requests`의 bank_name/account_number/account_holder). 단순환불(Q&A)은 미수집 → §6 참조.

## 4. 정식 반품 5단계 역물류 플로우

```
① 고객 반품 신청 (/returns → Shopify returnCreate)         ✅ 구현
② 관리자 반품 승인 (/admin/returns 상태 변경)              ✅ 수동
③ 택배 회수 (우체국 — 원래 출고 송장 재사용)               ❌ 미연동 (수동 신청)
④ 물건 수령 확인 (/admin/returns에서 "수령완료" 클릭)       ✅
⑤ 환불 처리 (카드→Toss / 무통장→이체) + "환불완료"          ⚠️ 환불 실행은 수동
```

**상태머신** (`/admin/returns`): `처리대기(pending) → 수거승인(approved) → 수령완료(received) → 환불완료(completed)`
- `수령완료` 단계에서 `getRefundPreview`로 Shopify 환불 미리보기 표시.
- `환불완료` 처리 시 알림 메일 발송 로직 있음(아래 §8).
- **CSV 내보내기**: `/admin/returns`의 "CSV 다운로드" 버튼 → 현재 필터(상태)에 해당하는 반품 목록을 CSV로 받음(주문번호·고객·사유·환불계좌·금액 포함, Excel 한글 호환). 배송팀/환불 담당에게 일괄 전달하거나 회수 신청 작업 시 사용.

---

## 5. 교환 정책

- **별도 교환 처리는 운영하지 않는다.** 교환 재고 관리 복잡성을 피하기 위함.
- 교환을 원하는 고객은 **"반품(환불) 후 원하는 상품 재구매"**로 유도.
- `/returns` 폼에 교환 옵션을 추가하지 말 것.

---

## 6. 계좌정보 빈틈 규칙 (Q&A 단순환불)

Q&A `환불` 분류는 **계좌 정보를 수집하지 않는다**(제목·내용·주문번호만). 그래서:
- **카드 결제 단순환불** → 카드로 되돌리니 계좌 불필요. 문제 없음.
- **무통장 단순환불** → 계좌가 있어야 이체 가능. **관리자가 고객에게 환불계좌를 먼저 받아야 한다**
  (Q&A 답변으로 요청하거나, 고객이 문의 내용에 적도록 안내).

> 운영 규칙: "Q&A 환불 분류는 카드결제 환불 위주. 무통장 환불은 계좌가 필요하므로 `/returns` 반품 폼으로 유도하거나 답변으로 계좌를 요청한다."

## 7. ⭐ 환불 처리 체크리스트 (빠뜨리면 정합성 깨짐)

환불은 "돈만 돌려주고 끝"이 아니다. **5가지를 모두** 해야 한다:

1. **돈 환불** — 카드(토스 취소) 또는 무통장(계좌 이체) 실행
2. **Shopify 기록** — 반품/환불 기록 반영 (returnCreate / refund)
3. **재고 복원** — 반품 상품이면 재고를 되돌림 (주문 취소 시 `restock`, 또는 Shopify 반품 처리)
4. **상태 업데이트** — `/admin/returns` 또는 `/admin/qa` 상태를 `환불완료`로
5. **고객 알림** — 환불 완료 통지 (메일/Q&A 답변)

> 하나라도 빠지면 "재고는 안 돌아왔는데 환불은 됨", "환불은 됐는데 고객은 모름" 같은 어긋남이 생긴다.

## 8. CS 채널 / 알림

- **인바운드(고객→우리)**: Q&A 게시판(`/qa`) **단일 채널**. 이메일/메신저 미운영.
- **아웃바운드(우리→고객) 알림**: `lib/actions/qa.ts`에 답변·환불완료 등 메일 템플릿(ko/ja) 구현됨.
  단 `RESEND_API_KEY` 미등록이라 잠들어 있음 → **Resend 가입 + 도메인 DKIM/SPF 인증 + 키 등록 시 자동 작동.**
- ✅ **반품 `환불완료` 메일은 고객에게 발송된다** (`lib/actions/returns.ts`).
  수신 주소 = Shopify 주문의 email(체크아웃에서 수집). 고객 locale(ko/ja)에 맞춘 템플릿, 관리자는 BCC로 기록 보관.
  이메일이 없는 과거 주문은 관리자에게 "고객 알림 미발송" 경고 메일로 폴백 → Q&A 답변 등으로 별도 안내할 것.

## 9. 미구현 · 대기 항목

| 항목 | 상태 | 선행 조건 |
|---|---|---|
| 카드 자동환불 (Toss cancel API) | ❌ 미구현 | 토스 live 키(MID `vabcstnvcf` 심사 통과) |
| 택배 회수 연동 (우체국 역물류) | ❌ 미연동 | 우체국 API 확인 + 셀메이트 Shopify 연동 여부 |
| 환불완료 메일 수신자 교정 | ✅ 완료 | 체크아웃에서 이메일 수집 → Shopify 주문 저장 → 고객 발송 (ko/ja) |
| 환불 경로 통합 뷰 | ⚠️ 보류 | 운영량 증가 시 |
| Resend 알림 활성화 | ⏸ 키 대기 | Resend 도메인 인증 + 키 등록 |

> 토스 실 키 전환 시: `NEXT_PUBLIC_TOSS_CLIENT_KEY`(결제창) + `TOSS_SECRET_KEY`(승인·취소·환불) 교체 — `.env.local` + Vercel 양쪽.
