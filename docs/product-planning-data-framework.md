# 상품 기획 데이터 프레임워크

> MakeShop(실판매) + Meta(수요·오디언스) 데이터로 **다음 상품 기획**을 의사결정하는 방법론.
> 실행 도구: `analysis/` (README 참조). 이 문서는 "왜 이 지표를 이렇게 보는가"를 정의한다.

---

## 0. 한 줄 요지

> **팔린 것(MakeShop)** 과 **반응한 것(Meta)** 을 겹쳐서, **수요는 있는데 공급이 못 따라가는 지점**을 찾는다.
> 그 지점이 곧 다음 상품 기획 슬롯이다. 두 방향으로 답한다 — **다시 만들까(재입고·확장)** vs **새로 만들까(신규)**.

두 데이터는 역할이 다르다:

| | MakeShop | Meta(Instagram/광고) |
|---|---|---|
| 답하는 질문 | **무엇이 실제로 팔렸나** (돈) | **무엇에 반응하나 / 누가 보나** (수요·오디언스) |
| 강점 | 매출·수량·사이즈·재구매 = 확정된 사실 | 아직 안 산 사람의 관심, 저장(=구매의향), 인구통계 |
| 약점 | 카탈로그에 **없는** 수요는 안 보임 | 매출로 이어졌는지 불확실 |

MakeShop만 보면 "지금 파는 것 안에서의 1등"만 안다. Meta를 겹쳐야 **카탈로그 밖의 기회**가 보인다.

## 1. 의사결정 질문 → 지표 매핑

### A. 다시 만들까 — 재입고·확장 (`restock_candidates`)
이미 검증된 상품에 더 투자할지. 네 신호를 결합:

| 신호 | 데이터 | 해석 | 가중치 |
|---|---|---|---|
| 최근 매출 규모 | orders (최근 90일) | 돈이 되는가 | `W_REVENUE` 0.35 |
| 성장 모멘텀 | orders (최근 vs 직전 90일) | 지금 뜨는가 | `W_GROWTH` 0.25 |
| 품절·재고소진 | products.status / inventory / 사이즈 판매중단 | 수요>공급인가 | `W_STOCKOUT` 0.20 |
| 인스타 반응 | instagram_media (게시물↔상품) | 관심이 살아있나 | `W_RESONANCE` 0.20 |

**점수 = 100 × Σ(가중치 × 정규화 신호)**. 정규화는 후보군 내 min-max(0~1).
→ **성장 + 품절신호가 동시에 잡히는 상품이 발주 1순위** (팔리는데 못 팔고 있음).

### B. 새로 만들까 — 신규 기회 (`new_opportunities`)
수요-공급 격차를 카테고리·테마 단위로 탐지:

- **수요(demand)** = 카테고리 성장 + 인스타 반응 (`W_DEMAND` 0.50)
- **공급격차(supply_gap)** = SKU가 얇을수록 + 매출비중이 낮을수록 높음 (`W_SUPPLY_GAP` 0.50)
- **점수 = 100 × (0.5×수요 + 0.5×공급격차)**

→ **반응·성장은 높은데 SKU가 2~3개뿐인 카테고리** = 카탈로그가 수요를 못 받치는 곳 = 다음 드롭 후보.
→ **반응 높은 해시태그 테마**를 현재 카탈로그와 대조 — 대응 상품이 없으면 그게 곧 빈 기획 슬롯.

### 스펙 결정 보조 지표
- **가격대 분석** (`price_bands`): 매출이 실제로 집중되는 가격 구간 → 신상품 정가 설정.
- **사이즈 분포** (`size_distribution`): 팔리는 사이즈 레인지 → 생산 사이즈 결정(꼬리 사이즈 축소/보강).
- **재구매·히어로** (`repeat_and_hero`): 재구매 고객 비중 높은 상품 = 라인 확장(색/사이즈/시즌 변주) 가치 큼.
- **함께 구매 페어**: 세트·번들 기획 힌트.
- **계절성** (`seasonality`): 카테고리별 월 매출 → **드롭 타이밍**(발주 리드타임 역산).

## 2. 지표 정의 (엄밀하게)

- **asof(기준일)** = 데이터의 마지막 주문일. "지금"을 데이터로 고정해 재현성 확보.
- **최근/직전 창** = 각각 최근 `RECENT_DAYS`(기본 90일)와 그 직전 90일.
- **성장률** = (최근매출 − 직전매출) / 직전매출. 직전이 0이고 최근>0이면 `신규상승`(성장 100%로 캡).
- **품절 점수(0~1)** = (소진 신호 잡힌 사이즈 수 / 판매된 사이즈 수) + status 가산(soldout·최근판매 시 +0.3), 1.0 상한.
  소진 신호 3종: ①status=soldout/discontinued ②inventory 재고0 ③직전엔 팔렸는데 최근 사라진 사이즈.
- **인게이지먼트율** = total_interactions / reach. **저장률** = saved / reach (저장은 구매의향 프록시로 특히 중요).
- **상품 반응** = 그 상품이 태깅된 게시물들의 인게이지먼트율을 reach 가중 평균.
- **재구매율** = 2회 이상 주문한 고객 / 전체 고객.

> 모든 점수는 **상대 비교용 휴리스틱**이다. 리포트는 점수와 함께 **구성요소(why)**를 항상 노출한다.
> 점수로 후보를 좁히되, **최종 판단은 근거를 보고 사람이** 한다.

## 3. 워크플로 (분기별 권장)

1. **수집** — MakeShop 주문/상품(엑셀 또는 API) + Meta 인스타 인사이트를 `analysis/data/` 로.
2. **실행** — `python3 run.py` → `output/product-planning-report.md`.
3. **의사결정 요약 읽기** — 재입고 상위, 신규 기회 상위, 반응 테마.
4. **재입고 확정** — 품절신호+성장 동시 충족 → 발주. 히어로 상품은 색/사이즈 변주로 확장.
5. **신규 슬롯 선정** — SKU 얇고 수요 높은 카테고리 1~2개를 다음 드롭 테마로.
6. **스펙 확정** — 가격대·사이즈 분포로 정가·사이즈 레인지 결정, 계절성으로 출시월 역산.
7. **가설 → 검증 루프** — 출시 후 다음 분기 리포트에서 그 상품의 모멘텀/반응으로 검증.

## 4. 한계와 주의

- **카탈로그 편향**: MakeShop은 *지금 파는 것* 안에서만 말한다. "없어서 못 산" 수요는 Meta·검색·문의(Q&A)·품절 신호로 보완.
- **게시물↔상품 매핑 품질**: 매핑이 없으면 상품별 반응이 비게 된다. 캡션에 `[P상품코드]` 표기 규칙을 두면 자동화됨.
- **인과 ≠ 상관**: 반응 높은 게시물이 매출을 냈다는 보장은 없다. 광고 전환(Marketing API)·CAPI Purchase로 교차검증.
- **작은 표본**: 신상품·비수기 카테고리는 표본이 작아 성장률이 튄다. 절대 매출과 함께 보라.
- **Shopify 전환 이후**: MakeShop 커넥터를 Shopify Admin API 커넥터로 교체하면(같은 정규화 스키마 유지) 분석 로직은 그대로 재사용된다. 이것이 `abc-migration`(Phase 5)과 이어지는 지점.
