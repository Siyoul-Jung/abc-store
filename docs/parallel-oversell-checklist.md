# 병행운영 오버셀 방지 — 상품 이전 운영 체크리스트

> 대상: 운영/재고 담당팀. 메이크샵 자사몰 ↔ Shopify **병행운영** 기간, 상품을 한 몰에서 다른 몰로
> 옮길 때 **같은 물리재고가 두 번 팔리는(크로스몰 오버셀)** 사고를 막기 위한 절차.
> 근거 정책: `docs/team-decisions.md` 1-1 **상품 분리(A안)**. 감사: `docs/pre-launch-integration-audit.md` ⑤.

---

## 왜 필요한가 (위험 정의)

- 메이크샵과 Shopify는 **재고가 실시간 연동되지 않는다**(A안: 양방향 싱크 안 함).
- 메이크샵 재고 = 셀메이트(바코드 스캔 WMS)로 차감 / Shopify 재고 = Shopify Admin.
- 따라서 **한 상품이 두 몰에서 동시에 "판매중"이면**, 같은 재고를 각 몰이 따로 팔아 **이중 판매(오버셀)** 발생. 두 고객이 결제했는데 실물은 하나 → 한 명은 취소·환불해야 하는 CS 사고.

## 절대 원칙

1. **한 상품은 한 몰에서만 판매중.** (겹침 금지 = A안)
2. **재고 진실 소스 = 그 상품을 지금 파는 몰.** 이전 전 = 메이크샵 / 이전 후 = Shopify.
3. 이전 중 **"양쪽 다 잠깐 안 팔림"(공백)은 안전 — 허용.** **"양쪽 다 팔림"(겹침 창)은 절대 금지.**

`✶ 핵심: 순서가 안전을 만든다 ────────────────────`
반드시 **① 메이크샵에서 내리고 → ② Shopify에서 켠다.** (내림 먼저)
반대(Shopify 먼저 켜고 메이크샵 나중에 내림)는 그 사이 **양쪽 다 팔리는 위험한 창**을 만든다.
잠깐 양쪽 다 품절로 보이는 건 손해가 거의 없지만, 이중 판매는 환불·신뢰 훼손 사고다.
`──────────────────────────────────────────────────`

## 상품 이전 절차 (메이크샵 → Shopify)

상품 1개를 옮길 때마다 순서대로:

- [ ] **1. 메이크샵에서 판매중지** — 해당 상품 품절처리 또는 숨김. (신규 주문 차단)
- [ ] **2. 진행 중 주문 정산** — 방금 전 들어온 미출고 주문분을 반영해 **실재고 확정**(셀메이트/메이크샵 기준).
- [ ] **3. Shopify에 재고 입력** — 확정 수량을 Shopify Admin 상품에 입력. 바코드/출고 스캔(WMS) 처리 방식도 확정(아래 의존성 참고).
- [ ] **4. Shopify에서 active 전환** — 이제 Shopify에서 판매 시작.
- [ ] **5. 겹침 없음 검증** — 두 몰에서 해당 상품이 **동시에 판매중이 아닌지** 눈으로 확인.
- [ ] **6. 이전 로그 기록** — 아래 표에 시각·수량·담당 기록.

## 롤백 (Shopify → 메이크샵, 필요 시)

같은 원칙, 순서만 반대 몰 기준:
- [ ] 1. Shopify에서 draft/비활성화 → 2. 실재고 확정 → 3. 메이크샵 재고 입력 → 4. 메이크샵 재오픈 → 5. 겹침 검증.

## 코드가 막아주는 것 vs 못 막는 것

| 오버셀 유형 | 방어 |
|---|---|
| **Shopify 몰 내부** (담은 뒤 품절→결제) | ✅ 코드가 막음 — 결제 확정 전 `availableForSale` 재검증(감사 ②), 품절 시 `/cart?notice=out_of_stock` |
| **크로스몰** (메이크샵+Shopify 동시 판매) | ❌ 코드가 못 막음 — **이 체크리스트(운영 규칙)로만 방어** |

## 의존성 (미해결 — 함께 확인)

- **Shopify 상품 출고 시 재고 차감 방식 미정**(`docs/ops-workflow-checklist.md` 5 참조): 셀메이트는 메이크샵용. Shopify로 옮긴 상품의 출고 스캔→차감을 어떻게 할지(셀메이트 API 연동 / Shopify 바코드 앱 / 수동) 결정 전까지는, **이전 상품 수를 소수로 제한**하고 출고분을 Shopify Admin에서 즉시 수동 차감할 것. (안 그러면 Shopify 몰 내부에서도 재고가 안 줄어 오버셀)
